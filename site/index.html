Claude Code plans. Atomic executes.

Claude Code is the brain: it designs, decomposes, decides. Atomic is the arm: multi-stage workflows, browser verification, independent verifier panels. atomic-remote is the wire between them — while you watch everything happen live in your terminal.

◈File-based bridge

An Atomic extension registers each session under ~/.atomic/agent/remote-bridge/ with a command inbox and an event outbox. Local IPC by files: no ports, no daemons, no network surface.

◈Official APIs only

Injection via pi.sendUserMessage / pi.sendMessage; lifecycle from documented events (input, agent_settled, tool_execution_end). Nothing reverse-engineered, nothing that breaks on upgrade.

◈Four command modes

prompt starts a turn · steer redirects mid-run · follow_up queues for after · interrupt aborts and takes over. Plus status, abort, live follow, durable tail.

Protocol v2 — replies you can trust

v2 shipped from an adversarial multi-agent design review: 30 proposals, each verified against Atomic's official docs, distilled to five guarantees.

01Attributed replies

Commands bind to their turn via the documented input event; every record carries an owner id. --wait concludes on agent_settled for your command — or refuses (exit 6) when concurrent typing makes attribution unsafe. It never guesses.

02Workflow-aware waits

If your command launches an Atomic workflow, --wait follows the run to its terminal lifecycle notice. "Workflow started" is never presented as the result.

03Heartbeat liveness

Sessions are live / stale / closed by a 5-second beacon — not by a transient engine pid that Atomic legitimately replaces. Delivery to a dead bridge is refused up front.

04Nothing deleted implicitly

list is read-only. History survives session shutdown. Cleanup happens only via explicit prune, closed sessions only, with symlink-escape guards.

05Fail-closed inbox

Schema-validated commands, O_NOFOLLOW + regular-file + 64 KiB checks, serial processing, at-least-once semantics with restart recovery. Every command gets an ack — malformed ones included.

→Exit codes are the contract

0stdout is the attributed reply
2timeout — still working, check later
6attribution uncertain — report nothing
7workflow detached — run id printed

Install in two minutes

Two sides: the plugin in Claude Code, the bridge extension in Atomic.

Add the plugin to Claude Code

claude plugin marketplace add uppifyagency/atomic-remote
claude plugin install atomic-remote@atomic-remote

Install the bridge into Atomic

From any Claude Code session:

/atomic-remote:setup

Then, inside the running Atomic session: /reload — you'll see atomic-remote bridge v0.2.0 active.

Command it

/atomic-remote:list
/atomic-remote:send auto "Build a snake game with your workflow" --wait
/atomic-remote:status my-project
/atomic-remote:follow my-project

Or just ask Claude in natural language — the bundled skill teaches it the whole flow, exit codes included.

Security model. Anything that can write into the bridge inbox commands your agent with your full user permissions. Directories are created 0700, files 0600, transport is strictly local files — no network surface. Do not widen the permissions; do not expose the inbox over a network.
